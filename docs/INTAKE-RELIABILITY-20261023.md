## Useful additions

- QR image intake uses the installed optional OpenCV decoder, never visits destinations, and requires editable review plus confirmation before a separate communication check. It supports multiple values and explains missing/damaged-code failures. Safe constructed QR and .eml fixtures are passive downloads for manual selection, never automatic checks.
- Original .eml files preserve MIME encodings and hidden HTML destinations. A metadata-only count identifies unscanned parts without filenames or attachment content. Attachment-only mail is explicitly incomplete, even with a subject; readable warnings stay intact and exports retain the unscanned-content limit. Invalid encodings and deeply nested structures produce incomplete/actionable outcomes instead of silent success or crashes.
- Desktop Link mode compares exact parsed hosts with an optional independently known website. Paths, credentials, query strings and ownership are not trusted or exported. Equality never establishes safety.
- A separate user-selected request panel provides fixed money/code/device/secrecy guidance for wording the checker missed. It never changes detected evidence, risk or the original report's summary/printout. Its own exports identify the user's selection and exclude source content.
- A dedicated print stylesheet exposes only the input-free fixed checklist. Desktop page exit and browser Back erase transient source, files, previews, OCR review, reference, evidence, print output and manual guidance. Clipboard waits have bounded fallbacks and stale-completion guards.
- Pocket includes opt-in literal English topic hints, individual Apply actions, six offline practice scenarios and manifest recovery/practice shortcuts. The user identifies requests. Hints and practice are separate from automatic scam analysis.
- Pocket explicitly counts literal addresses beyond its twelve-address inspection/comparison bound without inspecting or exposing them. Edits and Clear invalidate the notice and output. Fixed action exports contain no hostname report.
- Upload streams are capped before multipart parsing can spool excess data. Partial disk spools close immediately on rejection in the installed Starlette runtime. Invalid or incomplete uploads never reach analysis.
- Narrow negation handling prevents demonstrated false warnings when decimals, domains or honorifics separate safety advice from a matched action. Legacy history/reference parsing and independent later requests remain covered; this is finite English grammar support, not language understanding.
