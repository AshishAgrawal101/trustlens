# Broader content and context — v10

TrustLens now has three concrete areas: request and link warning signs, image-origin/provenance evidence, and claim/source-context review. The landing page presents the broader scope with a prominent Claim & context link while retaining all seven existing checker modes.

## Claim & context

Open /static/claim-review.html. Enter one specific claim, optional surrounding context, and up to two source addresses, quotations and publication dates. Only the claim is required. The local review identifies missing addresses/quotations/dates, same or different literal parsed hostnames, identical supplied quotations and future supplied publication dates. It produces questions and an independent checking plan.

Sources and quotations are supplied assertions: they are not visited or authenticated. A future date does not disprove a claim; recent publication does not establish truth; repeated wording and multiple websites do not establish independent evidence. No semantic contradiction detector, fact verdict, credibility score, model vote or web research is represented as implemented. Photo-caption review is contextual and does not inspect pixels. This keeps the new path useful without turning source metadata into an authority score.

Constructed photo-caption and headline examples load only after selection and require a separate review click. Copy/download export a fixed input-free plan, omitting all worksheet fields. Native print hides private worksheet content. No input is stored, no content request is made, and edits invalidate prior result/export state. Clear, page exit and persisted Back remove the fields. Fields have no form names and submission starts disabled until JavaScript handlers are attached, preventing a failed script from serializing private inputs through a native GET form.

The 25-case worksheet contract was frozen before predictions; all matched (17 reviews, eight fixed errors). These are authored software acceptance cases, not fact-checking accuracy or user-study evidence.

Independent review checked privacy, source/date semantics and lifecycle/export behavior. A download timing concern was resolved by adopting the existing main-app attached-anchor and delayed-revocation pattern. Controller tests verify fixed Blob content, clipboard failures/timeouts and late completion after Clear; actual saved OS downloads and real clipboard interaction were not tested.

Edge browser checks exercised both examples, explicit review, keyboard Tab from result to Copy, edit invalidation preserving draft sources, unsafe-scheme error without input echo, and Clear removing all eight fields. At 320px, document scroll width was 305px: no horizontal overflow. Temporary viewport override was reset. Screenshots and review outputs are in verification/scope-expansion/. No browser upload, permission bypass, physical phone, screen-reader audit or consenting-human study occurred.

Eleven previous source archives, the phone-test artifact, 104 original-source entries and all 34 protected v9 files remain unchanged. Another 432 existing v9 source entries outside the four intentionally updated integration/handoff files match. No model weights, runtime thresholds, native verifier or Pocket files changed. External v10 receipt records extracted checks with existing dependencies, not a clean install.

The image model remains unaccepted; additional-model resource/lineage gates and known OCR-wrap/repeated-soft-hyphen limits remain. Phone setup and publishing remain deferred. CAC eligibility still requires genuine significant student contribution/understanding and AI disclosure; software checks cannot supply this evidence.
