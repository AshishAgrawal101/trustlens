# Evidence labels and review priorities — v11

The Claim & context workspace now accepts optional user labels: unsure, supports, challenges or adds context. These describe the user's interpretation, not detected factual support. A selected role without a supplied address or quotation is excluded from the account comparison; a date alone cannot count as an account. Source labels appear separately from structural observations.

The review raises relevant support/challenge gaps without demanding equal weight for unsupported positions. Opposite user labels on identical trimmed quotations prompt a closer look at surrounding context, explicitly without claiming a detected factual contradiction. A visible next step prioritizes finding an original source, clarifying a future date, reading missing source text or examining a gap in the user's interpretation. Neither role count nor opposing labels resolves factual truth, credibility or source independence.

Two independently reproduced input/presentation issues were repaired: malformed HTTP(S) authority spellings are rejected before WHATWG URL can silently repair them, and quotation equality now states that surrounding whitespace was trimmed. Valid ports, IPv6 and Unicode-host parsing retain their existing behavior. The original analyze helper keeps its three-key result contract; the richer review helper serves the new UI. The initial additive result shape failed the old schema check; compatibility was restored rather than weakening the frozen contract.

All edits, role changes, Clear, page exit and persisted Back invalidate prior output. Clear resets both roles to unsure and wipes all eight original private fields. Copy/download still produce the exact same fixed input-free PLAN, with no selected roles or source content. No source is fetched, no storage/content API is added, and no truth/model verdict is produced.
