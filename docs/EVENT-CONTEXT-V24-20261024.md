# TrustLens v24 — event and publication context

Claim & context now accepts an optional supplied event date. It compares that date with publication dates attached to supplied source accounts, using calendar days across leap years and year boundaries. Earlier publication may describe an announcement or another event; the result does not infer contradiction, relevance, truth or source independence. Unknown dates stay blank. A date without an account does not create a source.

The existing worksheet and fixed input-free checking plan remain intact. Omitting the event date preserves previous outputs exactly. Editing the date removes the old result and disables exports; Clear, page exit and returning through Back erase it. The photo-caption example uses explicit constructed dates rather than interpreting “today.”

The standalone Pocket v24 export uses cache v20 and includes the same worksheet. Actual Edge checks loaded the new date field, calculated the constructed 1,461-day gap and retained missing-source questions while its HTTP server was stopped. At 320px the document fit its 305px client area and focused the result heading. A date edit cleared observations/disabled exports; reload returned an empty worksheet. Desktop 390px checks covered a two-day before/after leap-day case and date-only missing accounts.

Email checks also retain host and scheme-independent address observations for the first eight unique validated scheme-relative HTML targets, even when their visible label is ordinary text. Transport remains unknown. The adapter admits only six existing address-rule evidence families; it does not copy a synthetic HTTPS claim or visit a destination. Remaining targets contribute to existing partial-coverage guidance. Actual Email UI identified the constructed other.example destination and the text-before-@ concern without exposing credentials, paths or query values in evidence. Shared wording now refers to the parsed host “in this report,” because evidence groups can place it below a warning.

English-only wording-rule coverage is visible before Message, Email and Call checks. No automatic language detector was added.
