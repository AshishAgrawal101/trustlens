# Protected image-helper cleanup proposal

Read-only tiny-fixture exercise,2026-10-24. No runtime/model/weight load, scientific import, credentials call, final/Arena/user input, GPU or network work occurred. Patched only process-local references to load_runtime/decode_image using unittest.mock; all patches reverted. The actual shared decoder decoded a constructed2x2PNG. The protected file was SHA256-checked before/after and unchanged.

Three actual analyze_image paths were exercised: fake load_runtime RuntimeError; fake runtime.score RuntimeError; successful fake runtime.score returning0.2 with minimal metadata. In both failure cases the fixed ImageModelUnavailable wrapper's `__cause__.__traceback__` retained the `_analyze_image` frame, whose local `image` was exactly the decoded RGB image. getpixel remained usable while the exception was held. On success, a tracking reference also showed pixels remained open after return; without such a reference ordinary refcount cleanup may free them, but no explicit lifetime guarantee exists. The scoring lock released correctly in all cases.

This is a meaningful cleanup gap: a retained exception traceback can keep a maximum20MP RGB allocation alive beyond a failed request. It does not prove permanent unbounded leakage in the default server, which may release errors promptly. Repeated concurrent requests also decode before the scoring lock, but changing admission/concurrency would be a separate policy change; this proposal does not include it.

Smallest root-reviewed resource-only fix: import contextlib.closing and wrap the complete `_analyze_image` body after decode in `with closing(decode_image(content)) as image:`. Keep the full report construction/return inside that context so existing width/height access remains valid. This requires indentation of existing code, not mathematical edits. Alternatively use try/finally around the whole body with image.close(); either must cover load, scoring, component validation, report construction and successful return. Do not close before score/preprocess or before report dimensions are read.

Required regression tests before changing the protected file: retain a decode tracking reference and exception cause, assert pixels closed and lock released after fake load failure and fake score failure; assert successful fake score receives open pixels then closes them after the unchanged report is built; assert malformed score/component validation also closes; preserve original InvalidImage and fixed ImageModelUnavailable behavior. No real runtime is needed. Include exact report equivalence for the fake successful case before/after, plus existing image policy/source tests. Plain Pillow image context manager is insufficient for converted RGB; use explicit close/closing.

Contract to preserve: original decode/preprocessing, orientation, image pixel bytes passed to runtime, score/component scores, threshold, is_inconclusive policy, model identity/loading settings, model output/report/evidence/limitations and external API unchanged. No fitting, weights, metadata, calibration, evaluation or accepted performance result changes. This proposal is not authorization to modify the protected file or claim improved detection. Root decides whether to allow an explicit resource-only preservation exception.
