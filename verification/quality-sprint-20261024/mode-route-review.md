# Independent startup mode-route review

Current helper is startup-only and accepts exactly seven literal fragments: #check=text/screenshot/url/email/call/qr/image. It invokes the existing button click, then focuses/scrolls the labelled workspace. No data is parsed from parameters or populated into controls; no fetch/history/storage call exists. Integration must remain after primary-flow so its normal click listeners reconcile More tools and screenshot help before focus.

No blocking source defect found. Focusing workspace is a deliberate broad entry point: it announces the region and keeps the selected mode controls reachable; it does not jump straight into a possibly unfamiliar file picker. The following Tab proceeds through workspace controls, so users still encounter some navigation before the input. Root browser should verify this sequence and announcement, not label it a keyboard bug solely from source.

History behavior is intentionally limited. Changing only the fragment after load does not select another mode or destroy drafts. On Back/forward cache restoration, normal pageshow clearing preserves privacy and the currently selected mode may remain different from the startup URL. After a manual mode switch, copying/refreshing the unchanged #check fragment opens the initial routed mode, not necessarily the latest visible selection. This is a navigation tradeoff, not an input leak or automatic request. Directory links should be actual entries from the separate tools page, not same-page anchors advertised as live mode switches. If same-page routing is added later, it needs explicit draft/reset expectations and regressions.
