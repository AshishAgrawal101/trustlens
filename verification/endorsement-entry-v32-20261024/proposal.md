# Endorsement example: recommended small bridge

Recommend this slice, provided it remains a constructed worksheet entry rather than an endorsement checker. The existing Ads guide explains which comparison evidence is missing, but its only worksheet link opens an empty Claim form. The worksheet’s two examples are a caption and headline (`static/claim-review.html` and the controller’s `examples` object). A named endorsement example would demonstrate how the already-existing organizer applies to an everyday product recommendation, without adding another tool or interpreting sponsorship as truth or falsity.

## Minimal contract

- Add one existing-style **A sponsored comparison** example button, `data-claim-example="endorsement"`. Extend the exact, whole-fragment allowlist from `caption|headline` to `caption|headline|endorsement`; reuse the normal example handler and consume recognized fragments with the existing `history.replaceState` behavior. No automatic Review.
- Fixed claim: `These headphones last twice as long.` Fixed context: `Constructed sponsored headphone post. No comparison model or test settings are supplied. Identify the comparison models, test conditions and relevant independent results before interpreting the claim. Sponsorship alone does not establish whether it is true or false.` These are supplied example fields, not findings generated by the worksheet.
- Populate claim/context only. Reset all source URLs, quotations, roles, publication dates and event date through the existing `clear()` path; leave Sources closed. No invented source accounts, source count, event date or inferred challenging/supporting label. Review should still produce the unchanged no-source next step and generic fixed plan, not claim it analyzed an ad’s evidence.
- Make replacement explicit next to the example controls: examples replace the entire worksheet; select Review separately. This applies to button and fragment entry, including an already-populated worksheet. It is not a new confirmation modal.
- Add a normal guide link specifically labelled **Load a constructed endorsement example →**, with adjacent explicit replacement/separate Review wording. Preserve the existing general blank-workspace link for people working on their own material.

## Scope and integration risk

Core edits: `static/claim-review.html`, `static/claim-review.js`, canonical `static/phone/context.html`; focused route/controller/markup tests. No pure analysis, PLAN, export or stylesheet change should be necessary.

Root integration must explicitly rewrite the fragment-bearing canonical href `/phone/workspace/claims.html#example=endorsement` to `/static/claim-review.html#example=endorsement` in `render_desktop_context()`. Its current replacement matches a closing quote immediately after `.html`, so the existing generic replacement does **not** cover this new fragment link. Test both rendered desktop and canonical Pocket destinations; do not solve it with query bypass, duplicate guide markup or service-worker clearing. Shared Pocket workspace rendering preserves the Claim controller, so the same closed fragment contract can work there. Pocket cache/version and static-export refresh need their normal integration receipts before offline availability is claimed.

## Acceptance before release

1. Button, initial route and hashchange load exactly the fixed two fields; no API/fetch, Review, clipboard, download or source entry appears. Caption/headline remain unchanged and all three fragments are consumed without private data in history.
2. Existing private drafts/results and a pending copy completion cannot survive example replacement. Sources/date fields and labels clear; absent accounts remain absent. Explicit Review yields the existing generic no-source behavior and unchanged PLAN bytes.
3. Reject case variants, encoded tokens, trailing newline, extra query/content-bearing fragments and unknown examples. Clear, reload and persisted Back remain blank after a consumed example.
4. Desktop guide alias and Pocket canonical guide each point to the proper worksheet path with the exact fragment; all existing cards/links remain present. Browser check ordinary link → populated fields → separate Review, then Clear/reload, at a narrow width. Physical-phone behavior remains unverified.

This is a roughly 30-minute bounded extension of two already-proven mechanisms. The useful change is a discoverable guide-to-worksheet demonstration; it supplies no additional automatic conclusion. No application edits or browsing were performed for this proposal.
