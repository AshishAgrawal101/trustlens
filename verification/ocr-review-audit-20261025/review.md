One narrow actionable consistency gap reproduced: main checker lacks captured native-invalid cleanup, although context forms now have it. After screenshot extraction and an explicitly confirmed reviewed-text report, a constructed change to the required review checkbox without change/input followed by native invalid (no submit) leaves the old report visible and its summary copyable. Native constraint validation suppresses submit, however, and check-form has no invalid capture listener. Thus the exceptional no-change-event boundary bypasses existing result invalidation. Ordinary user checkbox toggling dispatches change and already works; this is not a claim that keyboard review can normally be bypassed, nor that old generated output was originally unreviewed. Actual browser/autofill behavior was not demonstrated.
