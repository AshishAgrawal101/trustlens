# Local image metadata backend

Implemented `POST /api/inspect/media` in the existing intake router. It reads at most the shared64MiB cap plus one byte, closes UploadFile in finally, and runs the helper in the existing threadpool. Shared decode_image enforces actual JPEG/PNG/WebP parsing,20million pixels and Pillow decompression/metadata limits; its fixed InvalidImage errors map400. No model runtime or native credentials function is called. Root integrates total multipart-body middleware coverage separately.

The exact structured contract is backend-contract.json. Dimensions retain both original header width/height and EXIF-adjusted display width/height. The temporary decoded RGB image is closed before reopening the original header. Optional EXIF returns only DateTimeOriginal (valid calendar/time, timezone unspecified), bounded printable Software/Make/Model and GPS-tag-presence boolean. No GPS coordinates/IFD, user/owner/serial fields, thumbnails, filename/path or raw metadata are returned. Text supplied in an allowlisted field remains unverified editable metadata; it is not a trusted software/camera identity. Absence of GPS tag means no such tag observed, not proof that location metadata never existed.

Unknown optional EXIF values/errors are omitted as null fields without exposing raw exceptions. A file failing shared validation is rejected400 rather than selectively salvaged. Fixed notice explicitly says editable/removable metadata cannot establish authenticity, AI origin, capture date, depicted story or location.

27 new constructed-fixture/boundary tests cover native JPEG/PNG/WebP, orientation1/3/6/8, nested validcapture time versus genericDateTime, invaliddate/time, bounded/control text, sensitive nonallowlisted tag omission, GPS IFD nonaccess, optionalEXIF failure, sharedpixel limit, malformedfiles, endpoint200/400 and boundedread/fileclose.
