# Scheme-relative HTML target adapter: independent product/privacy review

Read current app/analyzers/email.py, shared url.py rules, guidance.py consumers and tests/test_email_relative_targets.py. No source/test edits. Independently ran the new target suite: **13 passed in0.24s**.

No concrete correctness/privacy regression found in this bounded patch. The invented HTTPS prefix is confined to the parser/rule adapter; only an explicit six-ID scheme-independent allowlist is copied, not the shared report summary, transport evidence, actions or limitations. The host observation receives a scheme-relative title and source explicitly leaves transport/ownership unknown. Existing allowlisted rule details concern host/userinfo/IDN/subdomains/IP/shortening and do not echo private userinfo, path, query or fragment contents. No URL is visited or emitted as a constructed destination. Existing guidance matches retained userinfo IDs and provides a known-route action without asserting fraud.

Budget handling is explicit: first8 unique scheme-relative supplied href strings after surrounding ASCII-space removal, deduplicated across readable MIME parts; overflow is counted into existing zero-weight unknown email:links_incomplete. Literal HTTP(S) inspection has its separate existing budget. Hostname-label comparisons remain a separate bounded operation, so an overflow target can still have a label comparison; the current limitations disclose that distinction rather than claiming the target had no processing at all. Unsupported/hidden-character targets retain incomplete coverage. The aggregate count mixes unsupported visible occurrences and unique scheme-relative overflow, but neither evidence nor guidance claims it is a count of distinct destinations.

The tests exercise sensitive-field omission, first8/no9th shared-rule call, cross-MIME duplicates, future transport-rule exclusion, existing userinfo guidance, combined independent budgets and unavailable hidden-format targets. This review does not establish complete HTML/browser URL equivalence, rendered CSS/text visibility, reputation, source ownership or native mail-client behavior. No model, external source, browser upload or physical-phone test was used.
