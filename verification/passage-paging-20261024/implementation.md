# Literal passage paging implementation

Architecture selected before edits: optional third pageIndex=0 on existing SourceContext.find, retaining exact three-key schema and all two-argument outputs. No wrapper/module, second matcher or normalized mode. Each explicit call re-scans the existing bounded passage and retains at most five windows; no all-window cache or private snapshot. The only controller state is a page integer.

Pure contract: integer0..5999, fixed private error for invalid or nonexistent nonzero page; zero-match page0 remains valid. Existing exactcase/whitespace/nonoverlap/UTF16offset and ±160context/surrogate-boundary behavior remains. truncated still means total>returned windows, so last pages can be truncated because earlier windows are omitted. Controller endpoints therefore use total/page, not that flag. No new general invalid-Unicode guarantee is made.

Added native Previous five/Next five buttons, a live current range and global match ordinals. Navigation controls hide for<=5matches and disable at endpoints. Explicit Find keeps existing source-result focus. On navigation an enabled focused button stays focused for repeated keyboard use; if it becomes disabled, focus goes to the small current range before controls, never behind the windows. Current range scrolls to start. Status/cautions, literal text nodes, edge ellipses and whole-input formatting notices remain.

Existing invalidation boundaries now also reset page index, range, controls and formatting notice: original/passage edits, either Clear, example replacement, exit and persisted Back. A captured native invalid event clears stale source result even if the browser never dispatches submit. Revised-version edits remain independent. No automatic Find, network, persistence, URLstate, clipboard/export, source-authentication or truth score added.
