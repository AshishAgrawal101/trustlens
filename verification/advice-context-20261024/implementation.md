# Narrow credential-privacy and first-person refusal repair

Changed only app/analyzers/text.py and new tests/test_privacy_refusal_context.py. Inspected every application caller: Message and Call share analyze_text; email passes decoded subject/body text into analyze_text then shared communication_report; guidance selects fixed actions from existing evidence IDs. No API schema, score/confidence policy, URL interpretation or model changed.

A bounded helper suppresses secrecy only for an exact tell-anyone prohibition immediately followed by a known credential object, ending that sentence. Supported prohibitions are do/should/must-not, don't and never; objects are passwords/passcodes/PIN/OTP or verification/security/login/authentication codes, with optional your/my/the/a. All separators use the existing horizontal class, so no hard line is joined. The helper does not suppress a merely mentioned password, tell-bank instruction, quoted/embedded request, later secrecy ban or continued clause. In particular, comma/semicolon “only tell me” retains secrecy. Sentence-only scope is deliberate: broader tails could turn protective-looking wording followed by disclosure pressure into reassurance.

Only after that privacy guard, secrecy adopts consistent horizontal do-not spacing and should/must-not forms. It keeps the existing tell/contact/call recipient vocabulary and explicit secret phrase; no semantic classifier or generic code detection was added. Directly adjacent first-person I will not / I won't / I won’t before existing sensitive request verbs suppress that refusal's concern. Not-only, not-hesitate, non-first-person and later independent live requests remain detectable. Refuse-to/no-need grammar is not added.

Tests were written before app changes: RED40failed/30passed. After the narrow implementation the initial70tests passed. Seven extra continuation/spacing/source-excerpt probes make77 new tests total. Final relevant communication/context/history/sprint/source-offset suites:607passed in2.05seconds (green-tests.txt), including a30,000-character bounded-work guard and Message/Call/UTF8-MIME propagation. Existing independent-secrecy and conditional frames still pass. Original text/offsets are untouched; observed secrecy excerpts retain non-ASCII spacing.

The original nineteen-case before-results.json and its frozen cases remain unchanged. New after-narrow-fixes.json is explicitly a regression replay: sixteen authored expectations now match; three remain unsupported (contacting-bank using the message's number, I refuse to, and do-not-need-to). Ambiguous contact-route context is deliberately deferred. Credential privacy with a continuing clause may conservatively retain secrecy even if one clause is protective; no compound-clause comprehension claim is made. OCR wrapping and prior conditional-refusal limits also remain.

Public-example manifest/results and all historical diagnostic metrics remain untouched; these fixes were based on independently constructed context probes and paired regressions, not public-example misses. No private input, final/Arena data, cloud content API, training or inference was used. Test counts establish software behavior only, not population fraud/advice accuracy or sender trust.
