## Concrete inconsistencies

1. InputRequest ConfigDict(str_strip_whitespace=True) is inherited by UrlRequest. LeadingTAB/trailingLF are removed before BOTH /api/analyze/url and /api/inspect/url. The raw parse_address/inspect_url reject them because Cc/Cf/Cs checking happens before trimming. Allfour API cases (submitted URL and known-reference for both endpoints) return200 after trimming, whereas direct helpers reject. ASCII outer spaces and NBSP are accepted by helpers/APIs; interiorTAB/BOM are consistently rejected. This is not a decoder bug: Pydantic transforms first, silently changing the input contract.
2. static/app.js submits URL and nonempty reference with .trim(). JavaScript also trims BOM(U+FEFF), a formatting character which Python/Pydantic does not strip. Actual main-controller payload removes leadingBOM; anatomy controller intentionally preserves it. Direct APIs reject rawBOM400. Consequently Check can show a normal parsed-host result while the same visible field's Understand this address action reports hidden-character validation failure. Same mismatch occurs for known-reference values. tests/link_details.test.cjs preserves rawcontrols in outgoing payloads; tests/test_url_details.py requires helper rejection, but neither contract establishes equivalent API behavior because its shared request model trims first.

## Impact / intentional-whitespace distinction

Ordinary leading/trailing SPACE trimming is a reasonable paste-friendly policy and is already accepted by strict helpers. NBSP is also existing accepted whitespace, not an untested new refusal proposal. The actionable issue is conflicting Cc/Cf promises and same-field actions, especially BOM where the two actual UI paths differ. No accepted case points to a different hostname: accepted outputs all example.org. Interior controls still fail. No demonstrated redirect, credential leak, ownership verification or exploit follows. Severitylow consistency/reliability; do not advertise this as a new malicious-URL bypass.

Smallest coherent correction if root selects: make URL request fields preserve original input through request validation and submit raw URL/reference from the main checker, leaving the parser's existing ordinary-whitespace acceptance and Cc/Cf rejection authoritative for BOTH endpoints. Scope only UrlRequest+URL-mode payload handling, not text/email/call stripping. Optional-reference omission needs an explicit blank policy; ordinary ASCII spaces may omit, but a control-only reference should not silently disappear. Alternative intentionally permissive behavior would require aligning allhelpers/controllers and documenting normalization; silently retaining current split is less clear. No implementation authorized by this audit.
