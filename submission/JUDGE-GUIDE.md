# TrustLens: pause, check, act

For people examining messages, quotations, numbers and image context before acting or sharing. Local tools expose specific details and organize the next independent check; they do not authenticate a sender or decide whether a claim is true.

## A connected broader demonstration

Use the [one-post rehearsal](CAC-BROADER-STORY-DRAFT.md): one constructed park post, three questions. Compare the supplied quotation, compare 20/100 with 30/200 in Numbers, then manually enter the claim in the separate Claim worksheet. Clear each worksheet before leaving it. The 2:45 allocation is a planning budget, not a recorded or measured demonstration. Nothing transfers between worksheets.

The message sequence below is a separate alternative, not another segment to append to that recording.

## A 90-second demonstration

1. Click **A caller wants your code**, then **Check for warning signs**. Show the action first and its quoted evidence below. This is a constructed example, not a victim's message.
2. Click **A link hiding in plain sight**, then Check. Contrast displayed `bank.example` with the actual `account-review.example` host. Neither address is visited; legitimate tracking differences also occur.
3. Click **A normal safety reminder**, then Check. A code notification that says not to share it receives no matched warning. It still does not verify the sender or certify safety.
4. Select **Copy safe summary**, then Clear. The export omits private input; Clear removes the result content. Select **Already acted?**, then “I sent money.” No account details are requested and recovery is not promised.

Optional separate inspection: Screenshot extracts text for explicit review before checking; transparent screenshots may need an opaque contrasting copy. Image separates Content Credentials from experimental visual-origin evidence. Browser uploads and physical-phone operation remain unverified; do not present these as filmed demonstrations.

## Technical depth worth showing

| Capability | Observable behavior | Honest boundary |
|---|---|---|
| Screenshot intake | Installed Windows OCR, bounded hidden worker, explicit review stage | English OCR can miss text; no automated sender verification |
| Communication checks | Local rules, MIME parsing, displayed vs linked hostname, strict URL parsing; no destination fetch | Tracking differences can be legitimate; plain text may omit the link destination |
| Action selection | Different advice for codes, remote access, payments and overpayment | General guidance, not a recovery service |
| C2PA and image model | Cryptographic declaration verification alongside frozen visual inference | Origin is distinct from fraud; absent credentials prove neither |
| Privacy and resilience | No retained input history; safe summaries; timeouts and stale-response rejection | Local-server deployment; browser screenshot/image upload remains unverified |
